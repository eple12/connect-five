# ClaudyFive — 오목 엔진 + GUI

ClaudyEngine(체스)의 구조를 참고해 만든 15×15 **자유룰 오목**(5개 이상 연속이면 승리) 엔진과, ClaudyBot 대시보드와 같은 팔레트의 웹 GUI입니다. 설치할 것도, 빌드할 것도 없어요.

## 실행

`index.html`을 더블클릭하면 바로 열립니다. (엔진은 웹 워커에서 돌아서 생각하는 동안에도 화면이 멈추지 않아요.)
일부 브라우저에서 `file://` 워커가 막혀 있으면 아래처럼 로컬 서버로 여세요.

```bash
python -m http.server 8765
```

→ <http://localhost:8765>

단축키: `N` 새 게임 · `U` 무르기 · `H` 힌트

## 파일

| 파일 | 내용 |
|---|---|
| `engine.js` | 엔진 전체 (브라우저/Node 겸용, 인스턴스마다 독립) |
| `index.html`, `style.css`, `app.js` | GUI |
| `cli.js` | Gomocup(piskvork) 프로토콜 일부를 쓰는 텍스트 인터페이스 — Claudy의 UCI 대응 |
| `test.js` | 규칙·전술 테스트 (`node test.js`) |
| `selfplay.js` | 난이도 간 대국으로 강도 단조성 확인 (`node selfplay.js 5 4 20`) |

## 엔진 구조 (Claudy와 대응)

* **규칙 코어** — 패딩된 mailbox 보드, 증분 Zobrist 키, make/unmake.
* **평가** — 한 줄(±4칸)의 패턴 → 위협 등급(2, 닫힌 3, 열린 3, 4, 열린 4, 5)을 표로 만들어 두고(필요할 때 채우는 캐시), 돌을 놓거나 뺄 때 영향받는 줄의 빈 칸 점수만 갱신합니다. 정적 평가는 (내 칸 점수 합) − (상대 칸 점수 합 × 방어 가중치).
* **탐색** — PVS + 반복 심화, 전치표, 킬러/히스토리, LMR, 후보 폭 제한(정렬 상위 N수만).
  * 오목 전용: 5 완성 / 4 막기 / 쌍사(4-4)는 모든 노드에서 정확하게 처리, 열린 4·4-3 등은 칸 등급으로 인식, 리프에서는 **VCF**(4를 이어가는 필승 수순) 탐색이 qsearch 역할을 합니다.
* **난이도** (Claudy의 `strength.cpp`와 같은 방식 — 연속적인 손잡이 여러 개)

  | 손잡이 | 의미 |
  |---|---|
  | `depth` / `nodes` / `ms` | 최대 깊이, 노드 예산, 시간 |
  | `width` | 노드마다 살펴보는 후보 수 |
  | `noise` | 평가에 더하는 결정적 노이즈(표준편차) |
  | `blunder` | 그럴듯하지만 틀린 수를 둘 확률(%) |
  | `miss` | (하위 레벨) 4를 못 보고 지나칠 확률(%) |
  | `win4` | 열린 3/열린 4 위협을 읽는지 |
  | `vcf` | 4 연속 공격을 읽는 깊이 |

  1단계(입문)는 깊이 1에 큰 노이즈, 열린 3을 읽지 못하고 가끔 4도 놓치지만 **항상 돌 근처의 그럴듯한 곳**에 둡니다. 10단계는 깊이 24·6초·VCF 16수까지 읽습니다. 레벨 사이 승률은 `selfplay.js`로 확인했습니다 (L2>L1, L3>L2, L4>L3 …).
